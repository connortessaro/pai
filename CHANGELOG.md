# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [0.5.0] - 2026-09-25

### Added

- A docs site at https://connortessaro.github.io/pai/, published from `main`
  by the Docs workflow: the code reference (TypeDoc), guides to how keys,
  payments, caps, receipts and the local tools behave, and the interface
  reference. `npm run docs` builds it to `docs/site/`. Every export has a doc
  comment, and TypeDoc fails on a missing one or a broken link. The `Env`,
  `KeySource` and `Outgoing` types are now exported so the pages are complete.
- `docs/reference.md` now lists each command's subcommands and flags as `run()`
  reads them, whether it needs a key, the Phantom AI calls each command and MCP
  tool makes (method, path, body fields, headers sent and read, response), other
  network calls, and nested MCP input fields with their limits. `npm run docs`
  fails when `HELP`, `ENV_VARS` or the docs disagree with the code.
- `npm run coverage` fails if statements, branches, functions or lines drop
  under 80%.

### Changed

- On macOS, saved keys, wallets and the mail login are kept in the login
  Keychain. The file in `~/.config/phantom-key` holds only a pointer. Files
  saved before are moved into the Keychain the first time they are read.
  `PAI_KEYCHAIN=0` keeps them in files. Back up a wallet by exporting its key
  from the Keychain; copying the file no longer backs it up.

- `PHANTOM_BASE_URL` must start with `https://`. pai refuses plain http,
  localhost included, before it sends the key anywhere.

- Tests run on vitest 5.

### Security

- nodemailer is upgraded to 10, which fixes a high-severity advisory in 8.
  `@types/nodemailer` is dropped, since nodemailer now ships its own types.

### Fixed

- `pai <command> --help` prints help. Before, it ignored `--help` and ran the
  command, so `pai setup --help` installed the skill.

- `pai --help` now lists what the commands already accept: `--folder` and
  `--insecure` for `mail`, `--limit` for `memory`, `route get`,
  `browser status`, `--help` and `--version`. It no longer says `sandbox`
  takes `--space`, which it never read.

- `RouteTestResult` types `model` and `reason` as possibly `null`, and has
  `routed`, matching what the server sends.

- The saved key, a named key, the mail login and the pending-payment record
  are set to mode 600 every time they are written. Before, a file that was
  already there with looser permissions kept them.

## [0.4.3] - 2026-09-24

### Fixed

- A pending-payment record that can't be read now stops `buy --pay` and
  `autotopup` with `pending_corrupt`, instead of being read as nothing
  pending and paying again.

## [0.4.2] - 2026-09-24

No code changes: the first release published by GitHub Actions through npm
trusted publishing, with provenance.

## [0.4.1] - 2026-09-24

### Changed

- Published as `@connortessaro/pai` (`npm i -g @connortessaro/pai`, `npx -y
  @connortessaro/pai mcp`). npm refuses the unscoped `phai` as too close to
  `chai` and `ai`, so the scoped name replaces `phantom-pai`, which is
  deprecated and points here. `setup` registers the MCP server as `npx -y
  @connortessaro/pai mcp`. The command is still `pai`.

## [0.4.0] - 2026-09-24

The first version on npm. It is published as `phantom-pai`: the
`@phantom-ai` scope belongs to someone else.

### Added

- `docs/reference.md`, generated by `npm run docs` from `HELP`, the MCP tools
  and the new `ENV_VARS` list. CI fails when it is out of date.
- `buy --coin usdt`: USDT on Solana, next to USDC and SOL.
- `PHANTOM_WALLET_MAX_USD_PER_DAY`: the most the wallet may spend in 24
  hours, from the environment only. Defaults to `PHANTOM_WALLET_MAX_USD`.
- `PAI_MAIL_SEND_TO`: addresses or `@domain`s mail may be sent to, from the
  environment only.
- `setup --agent claude --provider [--model <id>]`: Claude Code's main loop
  runs on Phantom AI's `/v1/messages`, with the key supplied by
  `apiKeyHelper`. `--provider off` undoes it.
- `key show` with no name prints the key pai is using.

### Changed

- The package is `phantom-pai` (`npx -y phantom-pai mcp`), with a
  `phantom-pai` bin next to `pai`. It also installs straight from GitHub:
  `npx github:connortessaro/pai`, built on install by `prepare`.
- `buy` and the `buy_credit` tool call `/v1/purchase/solana` for every coin,
  defaulting to USDC. Phantom AI removed NOWPayments, so `btc`, `eth`,
  `usdttrc20` and the rest are refused before any call.
- Child keys are allowances: `pai child --limit <usd|none>` (and the
  `create_child_key` tool's `limit_usd`) sets how much of the parent's balance
  the child can spend. No credit moves. `--amount` still works as an alias;
  `--budget` is gone. `children` shows limit, spent and left.
- `burn` and `delete_key` report `forfeited_usd` instead of sweeping credit to
  the parent. Deleting a parent stops its children.

### Fixed

- A wallet payment could be paid twice. The pending record was cleared when a
  status check failed or timed out, so the next `buy --pay` or `autotopup`
  paid again. It is now kept until the payment is credited or reported dead.
- Two wallet payments started together could both pay. A lock file lets one
  run at a time.
- The wallet signed whatever amount, coin and mint the payment request named.
  It now refuses a request for another coin or mint, more USDC than asked for,
  or SOL worth more than 10% over the amount at Coinbase's price.
- `PAI_MAIL_MAX_PER_DAY` counted messages, so one send to many addresses used
  one unit. It now counts recipients, and parallel sends can no longer all
  pass it: sends take a lock and record before sending.
- SMTP on 587 and IMAP without TLS now require STARTTLS instead of using it
  only when offered, so a network that strips it gets no password. Configs
  made with `--insecure` are unchanged.
- With `PAI_MAIL_SEND=1`, the `create_child_key` tool requires `save_as`, so
  an email cannot get a new key into the context and then mailed out.
- `sandbox run` refuses an `--image` that isn't an image name (one starting
  with `-` read as an engine flag), and mounts with `--mount`, so a folder
  path with `:` works.
- A wallet payment called with an amount of `NaN` paid whatever SOL the
  payment request asked for, since every comparison with `NaN` is false.
  `buyAndPay` and `checkPaymentRequest` now refuse an amount that isn't a
  positive number.
- A wallet transaction that failed on chain was not reported as failed: the
  error Solana returns holds bigints, which `JSON.stringify` refused, so the
  payment stayed pending and counted toward the day. It now fails with
  `wallet_tx_failed` and is cleared.
- A payment request whose recipient or reference isn't a Solana address was
  recorded as spent and left pending before it failed. It is now refused
  before anything is recorded.
- The daily wallet cap refused amounts that add up to exactly the cap, such
  as $0.10 and $0.20 against $0.30, through floating-point error.
- A saved wallet named `env` or `file` could not be loaded.
- `key list|save|show|rm` needed an API key already set, so
  `PHANTOM_API_KEY=$(pai key show <name>)` failed in a fresh shell, and
  `verify --receipt=<r>` asked for a key that `verify --receipt <r>` did not.
- `burn` of the login key left the revoked key saved, so later commands ran as
  a dead key. It is now forgotten, as a named key is.
- `verify --receipt` crashed on a receipt whose payload is JSON `null`.
- `mail list --limit 0` fetched every message in the folder.
- `browser --space` took a path such as `../../x` and made a profile folder
  outside the state directory. Space names are now checked as memory's are.

### Removed

- `topup` and `merge`, and the `top_up_child` MCP tool. The server no longer
  has those endpoints.

## [0.3.0] - 2026-09-23

First public version.

The source lives in `src/pai.mts`, and `bin.mjs` runs the built `dist/pai.mjs`.

### Added

- `login` and `logout` to save a key (mode 600) so commands and the MCP server
  work without `PHANTOM_API_KEY`.
- `setup` to install the `phantom-ai` skill for pi, Claude Code, Codex and
  Cursor, with `--mcp` to register the MCP server too.
- `balance`, `budget get|set|clear` for the monthly and per-minute caps.
- `child` to create a child key with its own credit, lifetime, budget and rate
  cap, and `children` to list them with credit left and spent.
- `topup`, `merge`, `rotate` and `burn`.
- Keys saved by name with `key list|save|show|rm`, `child --save`, and
  `PHANTOM_KEY_NAME` to run any command as a saved key.
- `plan`, `plan set` and `plan clear` for money over a set period, and
  `route` to set which model `model: "auto"` runs and the rules that pick it,
  with `route test` to check.
- `buy` to add credit by crypto: USDC and SOL paid to Phantom AI on Solana,
  other coins through NOWPayments, with a Solana Pay link and `--wait`.
  `payment` checks a payment's status.
- An agent wallet: `wallet`, `wallet list|create|use`, `buy --pay` and
  `autotopup`. `PHANTOM_WALLET_MAX_USD` caps each payment, and pai reads it
  from the environment only.
- `verify --model` to make one small call and check its signed receipt, and
  `verify --receipt` to check a receipt against the published key without an
  API key.
- `memory add|search|list|show|rm|spaces`, a local markdown notebook for each
  agent under `~/.config/phantom-key/memory/`.
- `browser`, which runs agent-browser with a session and Chrome profile for
  each space, and `browser setup [--install]`.
- `sandbox run -- <command>`, a throwaway Docker or Podman container that runs
  as an unprivileged user, with no network unless `--net` and the folder
  read-only unless `--write`, and `sandbox check`.
- `mail setup|status|list|search|read|draft|send`, the user's own mailbox over
  IMAP and SMTP. Drafts only unless `PAI_MAIL_SEND=1`, and at most
  `PAI_MAIL_MAX_PER_DAY` messages in 24 hours.
- `mcp`, an MCP server over stdio with the same operations as tools.
- JSON output on stdout, `--table` for people, and exit code 2 when a key is
  rejected.
